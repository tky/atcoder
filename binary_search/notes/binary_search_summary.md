# 二分探索 学習まとめ

ロードマップ(README.md)全13問を完走した時点(2026-10-07)での総括。

## 一行でまとめると

**単調性がある → 二分探索できる**(区間は与えられていなければ倍々で作る)

有限区間は本質ではない。上限が不明でも、単調性さえあれば
「1, 2, 4, 8, … と倍々に広げて最初の『不可能』を ng にする」前処理
(指数探索、O(log 答え))で有限区間を製造できる。

## 実践チェックリスト

1. **軸に乗せる** — 探す対象を1次元の値として言い換える
   (配列の位置 / 答えの候補 / しきい値 t / 濃度 x …)
2. **単調性の検品** — 「mid で Yes なら、片側は全部 Yes か?」を式か一言の証明で確認。
   ここが全て。帯 `[Yes...Yes | No...No]` が崩れていたら二分探索は成立しない
3. **範囲と番兵** — 値域の両端 +1 まで番兵の土地を確保
   (配列なら `right = len`、答えなら値域の1つ外)。
   可能側の初期値が本当に可能であることを一度は確かめる
4. **終了条件** — 整数は「隣接で終了」(`ok + 1 < ng`)、実数は「回数固定」(100回)

## 道具箱(学んだパターンの索引)

### 基本形(Step 0-1)

- **不変条件から導出する**: `[0..left)` は v 未満 / `[left..)` は v 以上。
  暗記ではなく、この分割を保つように `<` と `mid + 1` を決める
- lower_bound の返り値 = 「v 未満の個数」。個数カウントに直結
- **+1トリック**: `より大きい` = `(v+1) 以上`(整数限定。実数では不可)
- **区間内の個数 = 境界2つの差**: `(r+1 未満の個数) − (l 未満の個数)`
- **最近値は pos と pos−1**: 1回探索して境界の両隣を添字で見る
  (値を ±1 して再探索するのは誤り)
- `==` での早期 break は重複バグの源。境界を潰しきるまで回す

### 探索対象の作り方(Step 1-1.5)

- ソート済み配列(そのまま)
- **累積和**(非減少なのでソート済み扱いできる。先頭0・len+1 で統一)
- **逆引き索引**(値 → 出現位置リスト。左から積めば自動で昇順)
- **自分で生成した単調列**(平方数リストなど)

### 言い換えのパターン(Step 1.5)

- 条件式を「i だけの式 = j だけの式」に分離 → 値の一致カウント
- mod の退化(和が 2M 未満なら「引かれるのは高々1回のM」)
- **寄与で数える**: Σ の順序交換 + 定数の括り出し。
  「ペアごとに計算」を「要素ごとの寄与 × 登場回数」にひっくり返す

### 答えで二分探索(Step 2-4)

- **最適化問題 → 判定問題**(「答えを x と決め打ちしたら実現可能か?」)。
  判定化すると問題自体が簡単になることが多い(丸太の等分、爆発の全体攻撃分の先引き)
- 単調性の**向き**は問題ごとに逆になる。ok/ng(または bottom/top)を
  紙で決めてから書く
- **分数計画法**: 比(平均)の最大化は `Σ(b_i − x·c_i) ≥ 0` に分母を払うと
  貪欲に落ちる(食塩水)
- 実数版: 隣がないので回数固定ループ。
  幅での打ち切り(`while top − bottom > eps`)は f64 の粒度で無限ループの危険
- f64 のソートは `sort_unstable_by(|a, b| b.total_cmp(a))`
- **締切への言い換え + EDF貪欲**(射撃王): Xを決め打ちすると各要素に
  「このターンまで」という締切が生まれ、判定はスケジューリングに落ちる。
  締切の早い順(EDF)の正当性は交換論法 — 「最適解のうち少なくとも1つは
  この形をしている」という**存在証明**であり、最適解の一意性は要らない
- 探索の上限は定数で雑に置かず、**入力から計算する**
  (`max(h + s*(n-1))` 等)と「ok側の初期値が本当にok」が構成から保証される

## 開発の型(バグを減らす手順)

1. naive版(resolve1)を先に書いてサンプルを通す(自明に正しい対照を確保)
   - ただし naive の計算量が「答えの大きさ」に比例する問題では、
     体力・値域を小さく絞った入力でしか使えない(Widespreadの教訓)
2. 答えで二分探索なら: **判定関数を先に書き、境界周辺の帯をテストで可視化**
   (false/false/true/true が並ぶテスト)してから探索を接続する
3. LCG(wrapping_mul/add、上位ビット使用)でランダム突き合わせテスト
4. 境界を突く定番ケース: 全要素が条件を満たす/満たさない、重複だらけ、
   ぴったり一致、両端(m=1, m=最大)

## ハマった罠の記録

- 番兵なしで `left = 0` から始めて「全要素が条件を満たす」ケースを落とす
- 累積和の込み/抜き(先頭0の欠如)で窓が1つずれる → 常に「len+1・先頭0」の型で作る
- usize の引き算アンダーフロー → `saturating_sub` / `checked_sub`。
  飽和させた値が「絶対にヒットしない」ことの確認を怠らない(コメントに残す)
- `t as i64` などのキャストで実数の小数部を切り捨てて精度を破壊
- 探索範囲の上限を値域ではなく所持金などに取ってオーバーフロー
- 対照実装(naive)自体の typo — 対照もサンプルで検証しておく
- 探索範囲の上限の見積もりミス(S≤10^9 を 10^5 と取り違え)。
  小さい値域のランダムテストでは検出できなかった →
  **ランダムテストの値域は「naiveが耐えられる限り、制約の上限まで振る」が原則**。
  小さい値域は同点・衝突を増やしたいとき(端数調整の検証など)に限って使う

## 二分探索の外側(構造の階段)

| 構造 | 手法 |
|---|---|
| 判定が単調(2帯) | 二分探索 |
| 単峰(山が1つ) | 三分探索 |
| 凸・滑らか | 勾配法・ニュートン法など |
| 構造なし | 全探索しかない |

探索の速さは常に構造との交換。「単調性があるか?」の検品は
「区間の半分を捨てても安全という保証があるか?」の検品である。
